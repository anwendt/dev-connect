# dev-connect v0.2.1 Release Notes

## Overview

`v0.2.1` improves tunnel stability for environments where enterprise proxies,
firewalls, or long-distance network paths close idle SSH or Kubernetes
port-forward streams.

This release adds configurable OpenSSH keepalive settings to generated
dev-connect SSH configuration.

## Highlights

- Added configurable SSH keepalive settings:
  - `ssh.serverAliveInterval`
  - `ssh.serverAliveCountMax`
  - `ssh.tcpKeepAlive`
- Enabled conservative keepalive defaults:
  - `serverAliveInterval: 30`
  - `serverAliveCountMax: 3`
  - `tcpKeepAlive: true`
- Updated generated temporary SSH config and managed user SSH config blocks to
  include keepalive directives.
- Added shorter keepalive examples for proxy-heavy environments.
- Updated troubleshooting documentation for tunnel drops caused by aggressive
  proxy idle timeouts.
- Added tests for SSH keepalive rendering, configuration defaults, and
  validation.
- Updated `.gitignore` to ignore macOS `.DS_Store` files.

## Configuration Example

For proxy paths that close idle connections aggressively:

```yaml
ssh:
  serverAliveInterval: 15
  serverAliveCountMax: 4
  tcpKeepAlive: true
```

`serverAliveInterval: 0` disables OpenSSH `ServerAliveInterval`. Negative
keepalive values are rejected during configuration validation.

## Security Notes

- No credentials are added to Kubernetes.
- No SSH private key material is read, copied, logged, or stored by
  `dev-connect`.
- Host key pinning remains mandatory.
- Keepalive settings only affect generated OpenSSH client configuration.

## Operational Notes

- This release reduces idle tunnel drops but does not introduce a persistent
  background supervisor process.
- Runtime reconnect after an already started `kubectl port-forward` process
  exits remains a future enhancement.
- Existing `dev-connect/v1` configuration remains compatible.

## Validation

Validated with:

```text
make test-security
make release-check
```
