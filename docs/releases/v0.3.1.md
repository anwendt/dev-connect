# dev-connect v0.3.1 Release Notes

## Overview

`v0.3.1` fixes the RBAC preflight of `connect`. Users without the right to
create pods could not connect, although their role allowed port-forwarding.

## Fixes

- The preflight asked `kubectl auth can-i create pods/portforward`. kubectl
  reads that as the pod named `portforward`, so the answer was `no` for every
  user who may not create pods. The preflight now asks
  `kubectl auth can-i create pods --subresource=portforward`.
- A denied check is reported as `kubectl port-forward permission denied`.
  Before, it surfaced as `verify kubectl port-forward RBAC: kubectl exited with
  code 1`, because kubectl exits with code 1 when it answers `no`.
- The operator guide and the operations runbook show the corrected command.
- Updated Helm chart metadata to `0.3.1`. The gateway itself is unchanged.

## Compatibility

- Existing `dev-connect/v1` client configuration remains compatible.
- Existing gateway deployments and their Role (`create` on `pods/portforward`)
  need no change. Only the client must be updated.

## Validation

Validated with:

```text
go test ./...
helm lint charts/dev-connect-gateway
git diff --check
```

The corrected command was checked against a cluster for two users bound only
to the gateway user Role: the old form answered `no`, the new form `yes`.
